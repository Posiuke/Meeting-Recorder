# Obsidian Frontmatter Integration

## Overview

This feature adds Obsidian-compatible YAML frontmatter to meeting recordings uploaded to Gitea. Each meeting upload now automatically includes a `meeting.md` file with metadata that can be used by Obsidian and other markdown-based tools.

## What is Obsidian Frontmatter?

Obsidian frontmatter is YAML metadata placed at the top of a markdown file, enclosed in `---` delimiters. It allows you to add structured metadata to your notes, which Obsidian and other tools can use for organization, search, and linking.

Example:
```yaml
---
creationDate: 2024-12-04
creationTime: 10:30:45
creator: BBB Bot
tags:
  - meeting
  - team-sync
sessionId: 2024-12-04_10-30-00__bbb-audio
---
```

## Features

### Automatic Generation

When a meeting is uploaded to Gitea, the bot automatically:
1. Generates a `meeting.md` file with frontmatter
2. Places it in the recordings directory
3. Includes it in the Gitea commit alongside the summary

### Metadata Fields

The generated frontmatter includes:

- **creationDate**: ISO date (YYYY-MM-DD) of when the recording was made
- **creationTime**: ISO time (HH:MM:SS) of when the recording was made
- **creator**: Name of the bot/recorder (from `DISPLAY_NAME` env var)
- **tags**: Array of tags (currently includes `bbb-recording` and `meeting`)
- **sessionId**: The session prefix/identifier for the recording

### File Structure

The `meeting.md` file contains:
1. YAML frontmatter with metadata
2. A heading and basic information about the recording
3. Session information

Example output:
```markdown
---
creationDate: 2024-12-04
creationTime: 10:30:00
creator: BBB Bot
tags:
  - bbb-recording
  - meeting
sessionId: 2024-12-04_10-30-00__bbb-audio
---
# Meeting Recording

Session: 2024-12-04_10-30-00__bbb-audio

This recording was automatically generated by BBB Bot.
```

## Implementation Details

### Core Functions

The feature is implemented in `src/obsidianMeta.ts`:

1. **`buildObsidianFrontmatter(opts)`**: Generates YAML frontmatter from options
   - Parameters: creator, date, tags, aliases, extraFields
   - Returns: Formatted YAML string with delimiters

2. **`writeObsidianMeetingFile(opts)`**: Creates a complete meeting.md file
   - Parameters: outputPath, creator, date, tags, aliases, extraFields, content
   - Returns: Path to the created file

### Integration Point

The feature is integrated into the Gitea upload flow in `src/summary.ts`:

- The `tryUploadToGitea()` function now:
  1. Generates `meeting.md` in the recordings directory
  2. Copies both the summary and meeting.md to the git repository
  3. Commits both files together

## Configuration

The feature uses existing environment variables:

- **DISPLAY_NAME**: Used as the `creator` field in frontmatter
- All other Gitea configuration (GITEA_REPO_URL, GITEA_USERNAME, etc.) remains the same

No additional configuration is required.

```bash

```

## Benefits

1. **Better Organization**: Metadata makes it easier to organize and search meetings in Obsidian
2. **Automatic Tagging**: Recordings are automatically tagged for easy filtering
3. **Timestamp Tracking**: Precise creation date and time for each recording
4. **Integration Ready**: Works seamlessly with Obsidian's dataview and other plugins
5. **No Breaking Changes**: Existing functionality is preserved; this is purely additive

## Example Workflow

1. Bot joins BBB meeting and starts recording
2. Meeting ends, recording is finalized
3. Summary is generated via LLM
4. **NEW**: `meeting.md` is created with frontmatter
5. Both files are committed to Gitea repository
6. In Obsidian, you can:
   - Search by date: `creationDate: 2024-12-04`
   - Filter by creator: `creator: BBB Bot`
   - Find by tag: `tag:#bbb-recording`
   - Use dataview queries to list all meetings

## Compatibility

- **Obsidian**: Fully compatible with Obsidian's frontmatter parsing
- **Other Tools**: Compatible with any tool that supports YAML frontmatter
- **Gitea**: No changes to Gitea workflow; files are committed normally
